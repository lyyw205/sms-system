# 무엇이 통합되나

> 작성 2026-08-06 · 근거: [`01-정리대장.md`](./01-정리대장.md)
> **아직 코드는 한 줄도 바꾸지 않았습니다.**

통합은 성격이 다른 **3가지**가 섞여 있습니다. 나눠서 봐야 합니다.

| 종류 | 무엇이 | 규모 |
|------|--------|------|
| ① 같은 코드 두 벌 → 하나로 | 어긋나면 사고 | 함수 18개 → 8개 |
| ② 흩어진 코어 → 제자리로 | 위치가 틀림 | 13개 승격 |
| ③ 각자 지키던 보호 → 관문으로 | 재발 방지 | 관문 3개 |
| ⚠️ 합치면 안 되는 것 | **그대로 유지** | 4종 |

---

# ① 같은 일을 하는 코드가 두 벌 (8건)

**가장 위험한 종류.** 두 벌이 어긋나면 조용히 다른 결과가 나옵니다.

## 1-1. 파티 MMS "그날 묵고 있나" 판정 🔴 최우선

```
지금   전체 스캔용  ──▶ SQL 로 판정
       단건 처리용  ──▶ 파이썬으로 똑같은 걸 직접 계산

나중   둘 다  ──▶ 같은 판정 하나
```

**왜 위험한가**: 전체 스캔에선 "대상"인데 단건에선 "아님"이 되면 **칩이 샙니다.**
문자가 안 나가거나 유령 칩이 남습니다.

**주의**: SQL 과 파이썬은 빈 문자열(`''`) 처리가 다릅니다. 단순 치환하면 동작이 바뀝니다.
→ 특성화 테스트로 현재 결과를 고정한 뒤 교체.

## 1-2. 추가요금 칩 삭제 함수가 3개

```
지금   추가요금 삭제    ──▶ 로직 직접 구현  (혼자만)
       업그레이드 약속  ──▶ 공통 함수 호출  (얇은 래퍼)
       업그레이드 후기  ──▶ 공통 함수 호출  (얇은 래퍼)

나중   셋 다  ──▶ 공통 함수 하나
```

**이미 공통 함수가 있는데 추가요금만 안 씁니다.**
인자를 "종류 하나" → "종류 여러 개"로 넓히면 그대로 합쳐집니다. 진단로그 접두사 파라미터가
이미 있어서 이벤트 이름도 보존됩니다.

## 1-3. 네이버 쿠키 저장 로직이 두 벌

```
지금   스테이블 쿠키 저장  ──┐
       언스테이블 쿠키 저장 ──┴──▶ 거의 똑같은 코드가 각각

       (공백 정리 → 형식 검증 → 다른 세션 커밋 → 감사로그 → 실제 호출 검증)

나중   공통 뼈대 하나 + 대상만 다르게
```

**효과**: 검증 규칙(50자 미만 거부 등)을 한 곳에서 고치면 양쪽에 적용됩니다.
지금은 한쪽만 고치면 다른 쪽에 구멍이 생깁니다.

## 1-4 ~ 1-6. 사실상 같은 함수 3쌍

| | 지금 | 나중 |
|---|---|---|
| 네이버 사용자정보 조회 | 커넥션 새로 여는 판 + 공유하는 판 | 커넥션을 인자로 받는 하나 |
| 순서 저장 (드래그) | 객실용 + 템플릿용 | 공통 헬퍼 하나 |
| 테넌트 접근 권한 검사 | 독립 함수 + 다른 함수 안에 복붙 | 하나 |

## 1-7. 발송 직전 새로고침 핸들러

```
지금   추가요금용    ──▶ "그날 배정된 예약 ∪ 그날 미발송칩 보유 예약"
       업그레이드용  ──▶ "그날 배정된 예약 ∪ 그날 미발송칩 보유 예약"   ← 똑같음

나중   합집합 계산은 공통 + 마지막 호출만 분기
```

## 1-8. 성별 판정이 세 곳에서 각각

```
지금   이벤트 문자 대상 선정  ──▶ SQL
       마케팅 문자 검색       ──▶ SQL (미묘하게 다를 수 있음)
       도미토리 배정          ──▶ 파이썬

       셋 다 규칙은 같음:
       "성별 표시가 맞거나, 해당 성별 인원>0 이면서 반대 성별이 없음"

나중   판정 헬퍼 하나 (SQL판 + 파이썬판이 짝을 이룸)
```

# ② 흩어진 코어가 제자리로 (13개)

"합친다"기보다 **"제자리를 찾아준다"**입니다. 계산으로 도출됐습니다.

## 가장 중요한 3개

### `stay_coverage_filter` — "그날 우리 집에 있는 예약" 판정

```
지금   스케줄링 모듈 안에 갇혀 있음
       그런데 6개 도메인이 씀 (칩·커스텀발송·파티·리포팅·예약·SMS)
       그중 10곳은 순환을 피하려고 함수 안에 숨겨서 import

나중   코어로 → 숨길 필요가 없어짐
```

이 함수가 **"체크아웃 날은 포함 안 함, 체크아웃이 비어있으면 당일 1박"** 규약을 혼자
책임집니다. 여기가 흔들리면 날짜 관련 전부가 흔들립니다.

### `reconcile_all_chips` — 문자 칩 5종 일괄 재계산

```
지금   4개 도메인이 씀 · 그중 17곳이 지연 import   ← 전체 최다
나중   코어로
```

**지연 import 17건**은 "모두가 필요한데 위치가 틀렸다"는 가장 강한 신호입니다.

### `date_range` — 체크인~체크아웃 밤 목록

```
지금   스케줄 유틸 안. 순환 때문에 "여기 물리적으로 잔류한다"고 주석까지 달려 있음
나중   코어로
```

## 나머지 10개

`today_kst` · `today_kst_date` (날짜 기준)
`on_dates_changed` · `on_status_cancelled` (뒷정리 순서)
`sync_naver_to_db` · `session_for_tenant` · `get_tenant_scoped_db` · `get_current_user`
`get_sms_provider_for_tenant` · `non_lodging_sections`

> **확산도 재계산 결과**: 지연 import 239건을 전부 반영해도 코어 13개는 그대로였습니다.
> 다만 그중 **10개가 지연 import에 의존**하고 있었습니다 — 코어일수록 숨겨진 호출이 많습니다.
> 코어로 올리면 전부 정상 import 가 됩니다.

# ③ 각자 지키던 보호가 관문 하나로

**가장 큰 변화입니다.** (Q5 = 넣기로 결정)

```
지금 (예약 필드 바꾸기)
   ┌─ 예약 수정 API ──────▶ 관문 통과 ✅
   ├─ 네이버 동기화 ──────▶ 관문 통과 ✅
   ├─ 연박 감지 ─────────▶ 직접 대입 ❌ (11곳)
   ├─ 동기화 내부 ───────▶ 직접 대입 ❌ (9곳)
   └─ 기타 ────────────▶ 직접 대입 ❌ (4곳)

나중
   모든 경로 ──▶ 관문 ──▶ DB
                  ↑
         우회하면 예외가 터짐
```

## 왜 이 방법이 확실한가

**이 저장소에서 이미 증명됐습니다.**

| 규칙 | 지키는 방법 | 우회 |
|------|-------------|-----:|
| 테넌트 격리 | 우회하면 **예외** | **0건** |
| 예약 필드 변경 | "이걸 쓰세요" 약속 | **24곳** |

같은 코드베이스, 같은 사람이 짰는데 결과가 갈렸습니다.
차이는 **"우회하면 터지게 만들었나"** 하나입니다.

## 관문 3개

| 관문 | 지금 | 나중 | 각자 지키던 함수 수 |
|------|------|------|-------------------:|
| 예약 필드 | 약속 (우회 24곳) | **강제** | 9 |
| 문자 칩 | 약속 (지금은 지켜짐) | **강제** | 8 |
| **방 배정** | **관문 자체가 없음** | **신설 + 강제** | 4 |

**방 배정에 관문이 없는데 4곳이 각자 지키고 있습니다.** 여기가 가장 취약합니다.

## ⚠️ 순서 주의

관문을 켜는 순간 우회 24곳이 **전부 테스트에서 터집니다.**
그래서 ①②로 우회를 전부 흡수한 **맨 마지막**에 켜야 합니다.

# ⚠️ 합치면 안 되는 것 (똑같이 중요)

조사하면서 **"비슷해 보이지만 일부러 다른 것"**을 찾았습니다.
명세에 **"통합 금지"**로 박아둘 예정입니다.

## 1. 파티 참여 집합 두 개

```
{1차만, 1+2차, 2차만}   ← 통계 · 체크인명단 · 매출용
{      1+2차, 2차만}   ← 파티 당일 MMS 전용 ('1차만' 빠짐)
```

넓은 쪽으로 합치면 **1차만 손님에게 오발송**,
좁은 쪽으로 합치면 **통계 누락**.

## 2. 방 충돌 시 정책이 정반대

```
방 배정할 때     ──▶ 규칙 위반자를 밀어냄   (성별 혼숙·정원초과라 못 둠)
날짜 정리할 때   ──▶ 밀어내지 않고 공존     (연장 때문에 기존 손님을 쫓아낼 순 없음)
```

같은 파일 안에 있지만 **둘 다 맞습니다.**

## 3. 문자 대상 선정 경로 3개

```
표준     구역·건물 필터 O · 액티비티는 공통필터가 격리 · 날짜별 중복방지
이벤트   구역·건물 필터 X · 액티비티를 직접 격리       · 날짜무관 중복방지
커스텀   구역·건물 필터 O · 칩 보유자로 사전 추림
```

**이벤트가 공통 필터를 안 타는 게 특히 중요**합니다.
신규 예약은 아직 방이 없어서 배정 조건을 걸면 대상이 0이 됩니다.

## 4. 파티차수 폴백 3가지

```
Python truthy   ──▶ None 과 '' 둘 다 예약값으로 폴백
SQL coalesce    ──▶ NULL 만 폴백, '' 는 그대로 채택
is not None     ──▶ None 만 폴백 (화면 표시용)
```

코드에 **"의도된 차이, 통일 금지"**라고 이미 적혀 있습니다.
